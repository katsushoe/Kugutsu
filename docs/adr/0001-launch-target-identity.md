# 起動対象の同一性とファイルリース

- Status: 採用（2026-10-13、実機未検証）

## Context

`AllowedLaunchTargets`はID、絶対実行パス、固定引数を設定で許可します。要求から任意の実行パスや引数を受けると、この許可範囲を維持できません。設定読込み後のファイル差替えも検出する必要があります。

## Decision

本体のSingletonレジストリに設定のコピーを固定します。初回の利用時に実行ファイルのボリューム、ファイルID、更新時刻、サイズ、SHA-256をメモリに記録し、以後の利用時に一致を照合します。

利用対象はドライブ文字付きローカル通常.exe、最大512MiBです。ファイルと祖先の再解析ポイント、UNC、デバイスパス、実ハンドルの最終パスが設定と異なる対象を拒否します。未存在の登録先はサーバ起動を妨げず、利用時に拒否します。

検証の読取りハンドルは書込み・削除共有を許可せず、後続の起動呼出しが終了するまでリースとして保持します。要求で指定できるのは登録IDだけで、固定引数を構造化配列で渡します。

## 代替案と不採用理由

- パスだけの照合: 同じパスの差替えを検出できません。
- 署名済みバイナリ限定: 未署名の開発アプリを許可する既存の用途と一致しません。
- 全対象を起動時に検証: 未導入の任意アプリが他のMCP機能まで妨げます。

## 影響範囲

アプリ、端末、PowerShell、ブラウザの起動対象解決へ適用します。App Execution Alias等の再解析ポイントによる起動はこの基盤では未対応です。対応が必要な場合は専用アダプターと別の設計判断を追加します。

## セキュリティ条件

設定は現在のユーザーが信頼するものを前提とします。初回利用より前の変更を検出する登録時ハッシュや署名検証はありません。親ディレクトリの差替えをOS起動処理と原子的に排除する保証もありません。初回の固定と同一性照合を、バイナリの安全性の証明として扱いません。

## 運用条件

正当なアプリ更新でも固定後の同一性が変われば拒否します。更新を確認後にKugutsuを再起動して再固定します。ハッシュとリースをディスクやログへ保存しません。検証中の取消はハンドルを解放します。

## 実装・検証・文書への対応

`LaunchTargetRegistry`が検証とリースを提供し、P10-02以降の起動処理が使用します。P10-01では基盤をDIへ登録し、実行APIを公開しません。ビルドとコード・仕様の読取りを確認し、実機起動とテストはユーザーの指示後に行います。仕様書8.4節とREADMEの実装範囲から本判断を参照します。
