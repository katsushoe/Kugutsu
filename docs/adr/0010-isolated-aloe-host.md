# ADR 0010: Aloeコンパイル・実行ホストの隔離

## Context / Status

2026-10-14。P15-02～P15-05としてコンパイル・実行・共通操作ホストと制限を接続しました。取消のキュー連携・Aloe受付もP15-06・07で接続しました。P15-08でシグナル登録・待機・解除の戻り値を扱うプリリュード関数を追加しました。固定CompilerLibのCompile(string)を使い、他プロジェクトのソースを変更しません。

## Decision

Kugutsu.AloeHost.exeを非表示の内部補助プロセスとして起動します。親は固定Aloe資産を確認して読取りリースを保持し、子も同じ確認後にメモリからアセンブリをロードします。直接アセンブリを使うメソッドはNoInlining境界の後に置きます。ソース・バイトコード・入力値・ネイティブ診断をディスクやログへ保存しません。

通信は標準入出力の私有パイプへ長さ付きUTF-8 JSONを渡します。1フレーム最大16MiB（P15-05で標準画像結果に対応するため拡張）、JSON深さ32、ソースは1～65536 UTF-16単位です。コンパイル結果のModuleは子のメモリへ保持し、親には命令数・関数数だけを返します。診断は固定コードALOE_COMPILE_ERRORとstage:compileで、入力を含む例外本文を返しません。行番号は取得していないため推測で付けません。

親のコンパイル期限はOperationTimeoutSecondsです。要求取消・期限超過・チャネル失敗では子を停止し、プロセスハンドルで終了を確認してからリースを解放します。停止要求が拒否された場合も終了確認が済むまで待ち、未確認のまま後続要求へ進みません。これはOS権限を制限するサンドボックスではなく、固定ライブラリとホスト能力の制限に加えたプロセス寿命の隔離です。

## 代替案

- 本体内Taskで直接Compile: parserの停止確認やプロセス障害の分離ができないため不採用。
- 独自言語へ暗黙変換: Aloeの構文・コンパイラーとの整合が失われるため不採用。
- 他プロジェクトのVM改造: Kugutsuの担当範囲外のため行いません。

## 影響・セキュリティ・運用

5つ目の内部実行プロジェクトと補助EXEが必要です。任意のEXEやDLLパスは受け付けず、インストールbin内の決まった補助プロセスだけを起動します。通常のMCP・JSON操作・ブラウザ操作には影響しません。実行対応時も一般用途I/Oを提供せず、操作ディスパッチと所有者文脈だけを接続します。命令数・呼出し数・メモリ制限の追加はP15-05、取消のキュー連携はP15-06です。

## 実装・確認・文書

コンパイルアダプター、私有フレーム、依存リース、DI、ソリューション、補助EXE出力を接続し、全体ビルドを確認します。実行・テスト・Aloeサンプルのコンパイルは未実施です。Aloe受付はP15-07で有効化しました。利用手順は[ALOE_BATCH.md](../ALOE_BATCH.md)を参照します。

## P15-05 実行制限

MaxAloeInstructionsは既定1000000、1～10000000。各命令実行前のTraceWriterで計数し、超過時はALOE_LIMIT_EXCEEDED、実行済み命令数と命令位置を返します。Trace文字列は保存や出力しません。観測を無効化するGCSetDebugと並行tickはコードに含まれる場合に拒否します。

ホスト呼出しはMaxBatchOperationsで制限し、上限を超える操作は送出しません。単一結果・私有フレームは16MiBまでです。結果が大きすぎる場合はhost_result位置で失敗し、既に実行された操作を再送しません。

AloeMemoryLimitMiBは既定256、128～1024。Windows Job Objectをソース送信前に割り当て、プロセスのコミットメモリ上限・同時プロセス数1・親終了時の子停止・未処理例外のOSダイアログ抑止を設定します。設定または割当てが失敗した場合はALOE_UNAVAILABLEとし、制限なしに継続しません。メモリ確保失敗を命令数超過と断定せず、VM失敗またはチャネル障害として報告します。

Windows構造とフラグは[MicrosoftのJob Object仕様](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information)と[拡張制限構造](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information)に従います。ビルドと設定JSONを確認しましたが、上限到達・停止・実機VM実行は未検証です。

## P15-08 Aloeシグナル関数

register_signalは既存登録操作を実行してsignalId文字列を返し、wait_for_signalはsignaled／timeout文字列を返します。unregister_signalは既存解除操作を実行してunregisteredを返します。条件JSONと待機時間は文字列で受け、親プロセスで厳密に解析して既存操作スキーマへ渡します。どの関数もAloe子プロセスへ所有者・ロック資格情報を渡しません。ロックの取得・更新・解除は引き続き外側のMCPツールで行います。

全ソリューションのビルドは警告0・エラー0です。Aloeソース例のコンパイル、VM実行、MCP実機連携は未検証です。
