# ADR 0008: 画像候補と明示ルールによる意味判定

## Status

採用。2026-10-14。入力欄の形状検出基盤を実装し、実機精度は未検証です。後続ドライバ・操作への接続は各実装項目で行います。

## Context

独自描画UIは標準UIAの型や値を提供しない場合があります。画像から操作候補を提示し、意味判定の根拠と不明な属性を呼び出し元へ渡す必要があります。

## Decision

PNGをメモリ内でグレースケール画像へ変換し、矩形の水平・垂直境界と内部の平坦さから入力欄候補を抽出します。入力欄候補は幅40以上、高さ12～128、縦横比2.5以上、左右境界の支持率0.6以上、内部平坦率0.7以上を既定の形状規則とします。境界の輝度差はVisualEdgeContrast（既定24、1～255）で変更できます。矩形の認識だけでは編集可否や内部のコントロール型を断定しません。

矩形・shape根拠・rule_scoreを保持し、確率へ読み替えません。未取得の有効・フォーカス・機密属性はnullとして後続へ渡します。用途semanticRoleと形状controlTypeを別属性に保ち、ラベル・周辺配置・プロファイルによる根拠を後続項目で加えます。LLMや外部画像サービスを認識パイプラインへ組み込みません。

ボタン候補は幅20以上、高さ12～96、縦横比1～12の矩形へ同じ境界・内部平坦率の検証を適用し、compact_flat_interior_v1の根拠を返します。入力欄とボタンの形状規則へ同時に適合する場合は両方の候補を保持し、内部型や業務動作を形状だけで確定しません。

## 代替案と不採用理由

- 形状だけで入力や編集を許可する: 対象の型・フォーカス・用途を確認できません。
- 最も高いスコアの候補へ暗黙に一本化する: 曖昧さの情報を失います。
- 対象アプリへTest Engineを追加する: 今回の画像ドライバは対象アプリの変更を前提にしません。

## 影響範囲

画像認識、ラベル関連付け、プロファイル、意味判定、画像ドライバの候補形式と後続操作へ適用します。この形状基盤だけではMCP操作を公開しません。

## セキュリティ条件

画像ドライバのフレームは参照IDとは別のメモリ表へ保持し、VisualSnapshotLifetimeSecondsで失効させます。最大16フレームかつPNG・輝度配列・BGRA画素配列の合計128MiBを上限とし、期限超過は要求時と1秒周期で整理します。参照は画像配列を直接保持せず、snapshotIdで照合します。画像探索は操作可能な前面ウィンドウを必要とし、暗黙に前面化しません。画像の取得・解析前後でウィンドウの世代・クライアント矩形・DPI・タイトル・入力先を確認します。画像で未取得の状態はnullです。

imgui_visualはTest Engineや内部ウィジェットIDを使わず、画像・OCR・矩形・明示プロファイルから共通候補を作ります。固定OCR資産のハッシュとx86ネイティブDLLの読込み・版を最初の可用性確認で検査し、認識直前にも資産を照合します。初回依存確認で不可用となった場合は資産を修復して本体を再起動します。可用性確認は文字認識の精度保証ではありません。候補の画像由来のEdit/Buttonは推定種類であり、内部型・有効・フォーカス・編集可否を保証しません。プロファイル付きボタンはinvoke、入力許可とフォーカス規則付き入力欄はset_value/send_keys、sensitive:falseの入力欄はget_valueを公開します。

プロファイルは[UI_PROFILES.md](../UI_PROFILES.md)のschemaVersion 1へ限定し、インストール範囲内のJSONだけを読み取ります。未知・重複フィールド、IDの重複、版・型・文字列・サイズ・パスの不正はUI_PROFILE_INVALIDです。内容のSHA-256を保持し、メタデータは最後に成功した読込みを示します。画像の型・用途・機密属性・入力許可を別の規則として保持し、プロファイルの入力許可だけでフォーカスや実際の編集可否を断定しません。

PNGのサイズ制限はOCRと共有し、画像・文字列を外部へ送信せず、ディスクやログへ保存しません。水平境界は4096本、矩形比較は65536回、出力候補は最大1000件で打ち切り、打切りをtruncated:trueで示します。重なる同種候補のIoUが0.85以上なら高いスコアの矩形を保持します。候補以外の状態を推測で補いません。

## 運用条件

画像参照の再検証では保存フレームの期限、ウィンドウ世代、矩形、DPI、タイトル、プロファイル版と内容SHA-256を確認します。候補自身と外部ラベル・文脈の局所BGRA画素を完全一致で比較し、変化時は再探索や再対応をせずUI_ELEMENT_STALEとします。中心と内側4隅のヒット先が同じルートウィンドウに属することも確認し、確認不能ならUI_TARGET_UNVERIFIEDです。これは画像の同一性確認であり内部ウィジェットIDの証明ではありません。意図したフォーカス・ホバー変更の後に候補自身の画素比較を除外する内部経路は後続操作だけが使用し、文脈と対象の検証は維持します。

generic_visualは同じローカル画像処理基盤を使い、一般的な矩形・ラベル候補へgeneric_visual用プロファイルだけを適用します。imgui_visualとの選択・参照・プロファイルを混同せず、UIAや他ドライバへ自動切替しません。任意の独自描画UIでの検出成功は保証しません。

意味判定は一致画面の各規則について、shape、label、relationのすべてをリテラル照合し、semanticRoleを別属性へ付けます。規則のID・プロファイルのID/版/内容ハッシュ・画面ID・ラベルと矩形の根拠を保持します。複数の規則やラベルへの一致はそれぞれ候補とし、最高スコアの意味へ自動で絞りません。未一致ならsemanticRoleはnullで、ラベルが複数ある場合もLabelを推測で一本化しません。最大1000候補・262144回の規則比較・1候補24件の画面根拠で打切りを伝達します。分類のrule_scoreと内部型・正解確率・編集可否を混同しません。

画面識別はプロセス名、任意のウィンドウタイトル条件、requiredLabelsのすべてに一致するプロファイル画面を返します。プロセスとタイトルはOrdinalIgnoreCase、OCRラベルはOrdinalのリテラル比較です。切り詰められたタイトルで一致を推測しません。複数の一致画面を暗黙に1つへ絞らず、プロファイル・画面・プロセス・タイトル・周辺OCRの根拠を保持します。最大128画面、必要ラベルごと最大4箇所の根拠で打切りを示します。明示したプロファイルが不明・別ドライバならUI_PROFILE_INVALID、対象・画面が確認できない場合はUI_TARGET_UNVERIFIEDです。

OCR単語を近接する行へまとめ、入力欄候補の左側・右側・上側、ボタン候補の内部の行を関連付けます。入力欄の内部文字列をラベルと扱いません。1候補に最大16の対応を残し、複数の候補・ラベル間の関係をスコアだけで一本化しません。OCR行は最大1000行・1行4096文字、行の結合探索は直近64行へ限定します。結合行がコントロール境界を跨ぐ場合にも外側のラベルを扱えるよう単語単位の代替候補を加え、全ラベルは最大2000件です。上限による不足はtruncated:trueです。OCR信頼度と位置関係のrule_scoreは別々に保持します。

低コントラスト・丸みの大きい形状・画像内文字や装飾により誤認や未検出があります。DPIにより物理ピクセルでの形状条件も影響を受けます。スコアを実機で検証済みの正解率として扱いません。参照は期限・世代・画素・文脈の再検証を行い、キー送信には2回のborder_color表示確認を必要とします。これらの実機有効性は未検証です。

## 実装・検証・利用者文書への対応

VisualRaster/VisualShapeDetector、設定・仕様・進捗を整合させ、全体ビルドと設定JSONを確認します。実機認識や自動テストは今回実施していません。
